# Bidirectional text (UAX #9)

`teak.bidi` (`src/core/bidi.zig`) is the Unicode Bidirectional Algorithm, Unicode 16.0, as a pure
module: no Host, no GPU, allocator only for working storage and results. Property data
(`Bidi_Class`, `Bidi_Paired_Bracket` + type) lives in `core/unicode_tables.zig`, generated by
`tools/gen_unicode.zig` from `extracted/DerivedBidiClass.txt` and `BidiBrackets.txt`.

## Pipeline

```
paragraph text --analyze--> Analysis{ para_level, levels[], classes[], offsets[] }   (per code point)
wrapped line [start,end) --lineLevels--> L1 levels --visualOrder / lineRuns--> L2 visual runs
```

- **One paragraph per `analyze`.** Split at hard line breaks first (`text_wrap.Line.hard_break`).
- `Direction.auto` runs P2/P3 (first strong, isolates skipped); `.ltr` / `.rtl` force level 0 / 1.
- Explicit embeddings, overrides and isolates are handled to depth 125; brackets pair per BD16
  (63-deep stack, `U+2329/232A` equivalent to `U+3008/3009`).
- Characters removed by X9 (LRE RLE LRO RLO PDF BN) keep their predecessor's level so they never
  split a run; `isRemoved(i)` identifies them.
- **Lines.** Apply per wrapped line: `lineRuns(gpa, an, line.start, line.hang)` returns runs left to
  right as displayed; odd `level` means the run's glyphs are drawn right to left (and
  `mirrored(cp)` gives the mirror of a bracket). Skip everything when `Analysis.isPlainLtr()`.
- **Caret.** `caretMove` moves one grapheme cluster in *visual* order for Left / Right. A logical
  index at a direction boundary has two visual positions, so the caret carries `trailing`
  (draw on the trailing edge of the cluster before `index` vs the leading edge of the one at it).
  Word jumps (Ctrl+Arrow) stay logical: keep using `unicode.nextWordBoundary` / `prevWordBoundary`.
- **Selection.** `selectionSpans` maps a logical `[sel_start, sel_end)` to visual x-ranges given the
  per-cluster advances; a selection across a direction change yields several spans.

## Conformance

`src/core/testdata/BidiCharacterTest_excerpt.txt` is every 300th data line of Unicode 16
`BidiCharacterTest.txt` (306 cases: levels after L1 + visual order); the module passes the entire
91,707-line file (verified locally, too slow for the default test run). Testdata is `-text` in
`.gitattributes`, so line endings are preserved on every platform.

## Not done yet (follow-ups)

- Rendering: `render/build.zig` and the text stage still draw each `text` Cmd as one logical run;
  they need to split a line with `lineRuns`, shape each run with its direction, and mirror brackets.
- `Editor` / `TextArea`: arrow keys still move logically; wiring `caretMove` (and a caret that
  carries `trailing`) is the next small step. Pointer hit-testing (`indexAt`) needs the same
  per-run treatment.
- L3/L4 (combining mark reordering, glyph mirroring beyond brackets) and `Bidi_Mirrored` beyond
  paired brackets belong to the shaper/renderer.
