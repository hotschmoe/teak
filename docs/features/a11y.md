# Accessibility (screen readers, switch access, voice control)

Teak renders to a canvas, so assistive technology (AT) sees nothing unless the framework tells it. The run loop
builds a **semantic tree** from the Cmd buffer, publishes it to the Host only when it changed, and turns what AT
does back into ordinary input. (Review §3.8 #4, milestone M3.)

```
view -> []Cmd -> layout -> []Rect -> a11y.buildTree -> []A11yNode --publishA11yTree--> Host (UIA / DOM mirror)
                                                                  <--pollA11yActions-- activate / focus / set value
                                                                  actions become a click, a focus Msg, typed keys
```

## What is exposed

`A11yNode { role, cmd_index, bounds, label, value, sel_start/sel_end, focused, disabled, state, selected, expanded,
level, live, modal, parent }`, in DFS order with `parent` pointing at the nearest emitted container, so the tree is
real (a tab list contains its tabs), not flat.

Intrinsic roles: `text`, `rich_text`, `button`, `text_input` (value + selection), `checkbox`/`radio` (`state` 0/1),
`slider` (`state` 0..1), `image`/`canvas`/`scene3d` (name = label), `scroll`, `divider`, `overlay` (a *modal* overlay
is a `dialog`, and hides the base layer, the same rule hit-testing uses).

Semantics beyond the Cmd kind come from one data hint, `A11yHint`, on `GroupStyle`, `ScrollStyle` and buttons:

```zig
cb.pushGroup(.{ .a11y = .{ .semantic = .tablist, .label = "Views" } });
cb.buttonA11y(.{ .select_tab = 0 }, "Parts", .{ .semantic = .tab, .selected = m.tab == 0 });
cb.popGroup();
cb.pushGroup(.{ .a11y = .{ .semantic = .status, .live = .polite } });   // announced when its text changes
cb.text(count_label);
cb.popGroup();
cb.textInputA11y(.focus_name, m.name, m.cursor, "New item");              // an input's accessible name
cb.buttonA11y(.{ .remove = i }, "x", .{ .label = "Remove milk" });        // name differs from the visible label
```

Semantics: `list listitem listbox option combobox tablist tab tree treeitem table row columnheader cell menu menubar
menuitem toolbar dialog status alert progressbar heading link`; `A11yHint` also carries `value` (progressbar 0..1),
`level`, `selected`, `expanded`, `live` (`off|polite|assertive`).

## Publishing (`RunOptions.a11y`, default on)

After the frame is built and diffed, `Runtime` rebuilds the tree only when Cmds, rects or the focus index changed,
compares it with an owned copy of the last published tree (`a11y.TreeCache`: fields and string contents) and calls
`Host.publishA11yTree` only on a real difference. Idle frames build and publish nothing.

## Actions back (`Host.pollA11yActions`, optional)

| AT request | What the run loop does |
|---|---|
| `activate` | a click at the node's centre against the previous frame's layout (`hit_test`): overlays, modals and disabled state apply; text inputs and sliders get focus instead |
| `focus` | dispatches the node's focus Msg (what Tab traversal dispatches) |
| `set_value` | focus, `Ctrl+A`, then the text as typed characters through the app's `keySpecialMsg` / `keyCharMsg` |
| `increment` / `decrement` | focus, then Right / Left |

There is no second mutation path: every action reaches `update` as the Msgs the app's own hooks produce.

## Platform truth table

| Platform | Tree | Roles | Actions back | Live regions | Notes |
|---|---|---|---|---|---|
| Web (zunk) | nested ARIA DOM mirror (`#zunk-a11y-root`), positioned over the canvas | all above (+ multi-line textbox reserved) | DOM click / focus / `input` event without key press (= set value) | `aria-live` on `status`/`alert`/hinted groups | tested with headless Chromium (`tools/a11yprobe.mjs`) |
| Windows | UIA fragment providers (`platform/win32.zig`), tree snapshot + StructureChanged | control types for every role | Invoke (button, tab, menuitem, link, option, treeitem, radio), Toggle (checkbox), Value (text input) via `ActionQueue` -> `pollA11yActions` | not yet | compile-checked from Linux, not run here |
| Linux | none yet | n/a | n/a | n/a | AT-SPI via AccessKit C: feasible, see below |
| macOS | no host | n/a | n/a | n/a | |

Focus sync on the web is two-way: Teak's focused node gets DOM focus; a DOM focus event (AT moving focus) becomes a
`focus` action. Keys that activate a native DOM control (Enter/Space on a mirrored button) do not also reach Teak's
keyboard path.

### Web wire format

64-byte records (parents before children) + a UTF-8 string heap: see the header of `src/platform/wasm.zig` and
zunk's `src/gen/js/a11y.js`. Role codes are ARIA-named and independent of the Zig enum order. Actions return as
16-byte records through `__zunk_poll_a11y_actions`.

## Probe tool

`node tools/a11yprobe.mjs todo examples/todo/dist` (also `notes`, and `dump <dist>`): loads the web build in headless
Chromium, reads the browser accessibility tree (`page.accessibility.snapshot`), asserts roles / names / values, and
drives the app **only through the DOM mirror**: DOM focus, typing into the mirrored textbox, `element.click()`, and
setting the textbox value like AT does. On hosts whose GPU driver lacks swapchain support in ANGLE-swiftshader set
`WEBSHOT_ANGLE=vulkan`.

## Linux: AT-SPI via AccessKit (feasibility, not vendored)

[accesskit-c](https://github.com/AccessKit/accesskit-c) (cbindgen header + a Rust staticlib / cdylib; its Linux
adapter is `accesskit_unix`, pure-Rust D-Bus via zbus, no libdbus / libatspi at link time) maps well:
`TreeUpdate` of nodes with stable ids and roles/states = `A11yNode`; its action requests (default action, focus,
set value, increment) = `A11yAction`. Measured here (aarch64, `cargo build --release`, `opt-level = "z"`, LTO): 84 s
cold build, **1.6 MB** stripped shared object (45 MB `.a` with debug info), links only libc + libgcc. Costs: a Rust
toolchain at build time, a node-id scheme that is stable across frames (`cmd_index` is not; derive one from
hint/label + sibling order or add an explicit `id`), and a worker thread delivering actions (queue into
`pollA11yActions`, as UIA will). Recommendation: an opt-in `-Daccesskit` build step later, behind `Host`; not vendored.
